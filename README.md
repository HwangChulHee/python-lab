# python-lab

파이썬 동작 원리 딥다이브. 백엔드 개발자 관점에서 "쓰고 있지만 설명 못 하는 것"을 없애는 저장소.

**목표 역량**
1. 어떤 파이썬 코드를 봐도 각 줄에서 무슨 일이 일어나는지 설명할 수 있다 (바이트코드·객체 모델 수준)
2. CPython 내부 구조(컴파일러, 평가 루프, 프레임, 메모리, GIL)를 아키텍처로 그릴 수 있다
3. Effective Python 3판(125 items)의 모든 규칙을 "외운 규칙"이 아니라 "원리의 귀결"로 설명할 수 있다

## 학습 방식

- 챕터는 **유닛** 단위로 진행. 유닛 = README(개념) + examples.py + exercises.py (+ 실측 시 measure.py)
- 유닛 README 구성: **지도 확인**(전체 그림의 어디인가) → 개념 → 자바와 비교 → 관측(pvmlab) → 백엔드 관점 → **실무 규칙**(EP 항목을 원리에서 유도) → 3문장 요약(직접 작성)
- 유제는 예측 → 관측 → 오차 수정 순서를 따른다. dis/pvmlab을 돌리기 전에 반드시 예측을 먼저 쓴다
  - **실무 규칙** 섹션이 Effective Python 항목을 흡수한다: 책의 결론을 방금 배운 원리에서 유도한다
  - 유제에는 해당 항목의 위반 코드를 원리로 진단·수정하는 문제가 포함된다
- 새 유닛 시작 시 이전 내용 회수 질문 1개 (간격 반복)
- 부(Part)가 끝나면 통합 유제 세션
- 새 개념마다 자바와 비교: "같다"(이해 가속) vs "비슷해 보이지만 다르다"(오해 방지)
- 블로그(티스토리) 초고는 유닛 README 기반
- 관측 장비: `tools/pvmlab/` — 진짜 바이트코드를 재현 엔진으로 실행하며 프레임/값 스택을 시각화. HTML 트레이스는 언제든 봐도 되고, 엔진 코드는 해당 장에서 뜯는다. 전 장 통과 = pvmlab 전체가 설명 가능해지는 것

## Effective Python 3판 병행 방법

- 각 챕터 옆 `[EP: ...]`가 대응 항목. **챕터를 끝낸 뒤** 해당 항목을 읽는다 (원리 먼저, 규칙 나중)
- 읽을 때 기준: 이미 아는 내용으로 읽히면 통과, 새로우면 유닛 복습 신호
- Item 2(PEP 8), 118(독스트링)은 특정 챕터 없이 전 과정에서 상시 적용
- 커버리지: 125개 항목 전부가 아래 챕터 중 하나에 배치됨
