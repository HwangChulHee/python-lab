# u2. def는 선언이 아니라 실행문이다

## 질문

파이썬 파일은 위에서부터 한 줄씩 전부 실행된다. `def`도 예외가 아니다.
그런데 `def f(): ...` 줄을 "실행한다"는 건 무슨 일이 일어나는 것인가?
함수 본문이 실행되는 건 아닌데.

---

## 1. 다른 언어와 뭐가 다른가

자바나 C에서 함수/메서드 정의는 **선언(declaration)**이다.
컴파일러가 "이런 함수가 있다"고 기록해 두는 것이고, 실행되는 코드가 아니다.
그래서 이런 게 안 된다.

```java
// 자바 — 컴파일 에러
if (조건) {
    void f() { ... }      // 조건부로 메서드를 정의할 수 없음
}
void greet() { ... }
void greet() { ... }      // 같은 시그니처 중복 정의 → 컴파일 에러
```

파이썬은 다르다. `def`는 **실행되는 문장**이고, 실행되면 값(함수 객체)을 만들어
이름에 붙인다. 즉 아래 두 줄은 거의 같은 일을 한다.

```python
def f():
    return 42

# ↕ 개념적으로 같음

f = <42를 반환하는 함수 객체>
```

`def`는 "함수를 선언한다"가 아니라 **"함수 객체를 만들어서 이 이름에 대입한다"**이다.

---

## 2. 두 개의 객체가 있다

여기가 핵심이다. 함수 하나를 만들 때 파이썬은 객체를 **두 개** 다룬다.

### 코드 객체 (code object)

함수 **본문을 컴파일한 결과**다. 바이트코드 덩어리라고 보면 된다.

- **언제 만들어지나**: 컴파일 시점 (파일을 읽어 바이트코드로 바꿀 때, 딱 한 번)
- **뭐가 들어 있나**: 바이트코드, 본문에서 쓰는 상수들, 지역 변수 이름 목록, 인자 개수
- **성격**: 불변(immutable). 한 번 만들어지면 안 바뀐다.
- **없는 것**: 기본값, 클로저 변수 값, 함수 이름 바인딩

### 함수 객체 (function object)

우리가 `f`라고 부르며 호출하는 **그것**이다. 코드 객체를 감싼 포장지다.

- **언제 만들어지나**: `def` 줄이 **실행**될 때 (실행될 때마다 매번 새로)
- **뭐가 들어 있나**: 코드 객체에 대한 참조 + 기본값(`__defaults__`) +
  클로저(`__closure__`) + 이름(`__name__`) + 독스트링(`__doc__`) + 전역 네임스페이스 참조
- **성격**: 가변. 속성을 마음대로 붙일 수 있다.

### 비유

- **코드 객체 = 악보.** 곡 자체. 한 번 인쇄되면 안 바뀐다.
- **함수 객체 = 연주자.** 그 악보를 들고 있는 사람. 같은 악보를 든 연주자가
  여러 명 있을 수 있고, 각자 다른 조율(기본값, 클로저)을 갖는다.

`outer()`를 두 번 호출하면 **연주자는 두 명**이 생기지만 **악보는 하나**를 공유한다.
악보를 다시 인쇄할 이유가 없기 때문이다.

### 실제 확인

```python
def outer():
    def inner():
        return 42
    return inner

a = outer()
b = outer()

a is b                      # False  ← 함수 객체는 다름 (연주자 2명)
a.__code__ is b.__code__    # True   ← 코드 객체는 같음 (악보 1개)
```

## 3. `def` 한 줄이 바이트코드로는 세 줄이다

`outer`를 `dis`로 뜯으면 이렇게 나온다.

```
LOAD_CONST   1 (<code object inner>)   ← ① 악보를 스택에 올림
MAKE_FUNCTION                          ← ② 악보로 연주자를 만듦
STORE_FAST   0 (inner)                 ← ③ 연주자에게 'inner'라는 이름표를 붙임
```

각각을 뜯어보면:

**① `LOAD_CONST <code object inner>`**
`inner`의 코드 객체가 **상수 취급**된다는 점이 중요하다.
`1`이나 `"hello"` 같은 리터럴과 똑같은 자리에 있다.
즉 `inner`의 본문은 프로그램이 실행되기 **전에** 이미 다 컴파일돼 있었다.

**② `MAKE_FUNCTION`**
`def`를 "실행한다"는 게 실제로 이 명령이다.
악보(코드 객체)를 받아서 연주자(함수 객체)를 새로 만든다.
`outer()`가 호출될 때마다 이 명령이 다시 돌아서 새 함수 객체가 생긴다.

`MAKE_FUNCTION` 옆의 숫자는 플래그다. 붙일 게 없으면 0, 기본값이 있으면 1,
클로저가 있으면 8 같은 값이 된다. 예제에서 `inner`는 아무것도 안 받아서 0이다.

**③ `STORE_FAST inner`**
만든 함수 객체를 이름에 바인딩한다. 이게 "할당문에 가깝다"의 실물이다.

## 4. 기본값은 어디에 저장되는가

`greet` 예제 출력을 다시 보면 이상한 점이 있다.

```python
def greet(name, greeting="hello"):
    """인사한다."""
    return f"{greeting}, {name}"

greet.__defaults__            # ('hello',)      ← 함수 객체에 있음
greet.__code__.co_consts      # ('인사한다.', ', ')  ← 코드 객체엔 'hello'가 없음!
```

기본값 `'hello'`가 코드 객체의 상수 목록에 없다. 왜?

기본값은 **함수 본문에 속한 값이 아니기 때문**이다.
본문이 실행되기 전에, 함수를 만드는 쪽(여기선 모듈)이 미리 준비해서
`MAKE_FUNCTION`에게 "이 값을 기본값으로 달아줘"라고 넘겨주는 값이다.

그래서 이렇게 된다:

> 기본값은 `def`가 **실행되는 순간 딱 한 번** 평가되어 함수 객체에 붙는다.
> 호출할 때마다 다시 평가되는 게 **아니다.**

이 사실이 파이썬에서 제일 유명한 함정의 원인이다.

```python
def add_item(item, basket=[]):
    basket.append(item)
    return basket

add_item("a")    # ['a']
add_item("b")    # ['a', 'b']   ← 왜 초기화가 안 되지?
```

`[]`는 `def` 줄이 실행될 때 **한 번** 만들어져 함수 객체의 `__defaults__`에 들어간다.
호출할 때마다 새 리스트를 만드는 게 아니라, 그 **하나의 리스트를 계속 재사용**한다.
(04장에서 본격적으로 다룬다. 지금은 "구조적으로 왜 그런지" 감만 잡으면 된다.)

## 5. 함수 객체는 그냥 객체다

함수 객체가 특별한 문법 요소가 아니라 **평범한 객체**라는 게 파이썬의 큰 특징이다.

```python
def greet():
    return "hi"

greet.call_count = 0        # 속성을 붙일 수 있다
funcs = [greet, print, len] # 리스트에 담을 수 있다
g = greet                   # 다른 이름에 대입할 수 있다
```

여기서 "함수는 일급 객체(first-class object)"라는 표현이 나온다.
값처럼 다룰 수 있다는 뜻이다 — 변수에 담고, 인자로 넘기고, 반환하고, 자료구조에 넣고.

## 6. 여기서 파생되는 것들

`def`가 실행문이라는 사실 하나에서 여러 특징이 따라 나온다.

**조건부 정의가 된다**
```python
if sys.platform == "win32":
    def path_sep(): return "\\"
else:
    def path_sep(): return "/"
```
실행문이니까 `if` 안에 들어갈 수 있다.

**재정의는 에러가 아니라 덮어쓰기**
```python
def hello(): return "first"
def hello(): return "second"
hello()    # "second"
```
`hello = 함수1` 다음에 `hello = 함수2`를 한 것과 같다. 나중 대입이 이긴다.
(참고: 이것 때문에 파이썬에는 **오버로딩이 없다.** 같은 이름의 함수를
인자 타입별로 여러 개 정의할 수 없다.)

**데코레이터가 가능하다**
```python
@logger
def add(x, y): return x + y

# ↕ 완전히 같음

def add(x, y): return x + y
add = logger(add)
```
`@deco`는 `f = deco(f)`의 문법 설탕일 뿐이다.
`def`가 값을 만들어 이름에 대입하는 실행문이기 때문에, 그 값을 가로채서
다른 걸로 바꿔치기할 수 있는 것이다. (→ 11장)

**`class`도 똑같이 실행문이다**
클래스 본문이 실행되고, 그 결과로 클래스 객체가 만들어져 이름에 바인딩된다.
`class`도 사실상 할당문이다. (→ 13장)

## 7. 백엔드 관점

FastAPI가 이렇게 동작하는 이유가 정확히 이것이다.

```python
# routers/users.py
@app.get("/users")
def list_users():
    ...
```

이 모듈이 **임포트되는 순간** `def` 줄이 실행되고,
데코레이터 `@app.get("/users")`가 호출되어 함수 객체를
FastAPI의 라우팅 테이블에 **등록**한다.

서버가 첫 요청을 받기 전에 이미 모든 경로가 등록돼 있는 이유는
"임포트가 곧 실행"이고 "`def`가 실행문"이기 때문이다.

이 관점이 없으면 "왜 라우터 모듈을 임포트만 해도 경로가 잡히지?"가
영원히 마법으로 남는다. Django의 모델, SQLAlchemy의 테이블 매핑,
pytest의 fixture 등록도 전부 같은 원리다.

## 정리 표

| | 코드 객체 (`__code__`) | 함수 객체 |
|---|---|---|
| 비유 | 악보 | 연주자 |
| 생성 시점 | 컴파일 시점, 1회 | `def` 실행 시점, 매번 |
| 만드는 명령 | (컴파일러가 상수로 준비) | `MAKE_FUNCTION` |
| 담는 것 | 바이트코드, 상수, 지역명 | 코드 객체 참조, 기본값, 클로저, 이름 |
| 변경 | 불변 | 가변 (속성 추가 가능) |
| 같은 def 여러 번 실행 | 공유됨 | 매번 새로 생성 |

1. 파이썬의 def는 선언이 아니라 실행문이다.
2. 따라서 파이썬의 함수는 조건문에서 정의될 수 있고, 덮어쓰기가 가능하다. 그리고 덮어쓰기를 응용해서 데코레이터 문법이 가능하다.
3. 파이썬의 함수는 함수객체와 코드객체로 나누어지며 코드 객체는 함수 본문 자체를 컴파일한 바이트코드 덩어리라고 보면되고, 함수 객체는 코드객체를 포함하며 함수 정의 시, 결정되는 기본값과 클로저, 이름 등이 들어간다.
