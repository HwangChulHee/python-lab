# u4. 인자 전달의 진실 — 값도 아니고 참조도 아니다

## 지도 확인

u2에서 `b = a`가 화살표 복사임을 봤다. 함수 호출도 똑같다.
`f(a)`를 부르면 무슨 일이 일어나는가? 자바의 "값에 의한 전달"도,
C++의 "참조에 의한 전달"도 아닌 파이썬만의 방식을 정리한다.
01장의 마지막 유닛이자, u1~u3가 전부 모이는 곳이다.

## 개념 1 — 인자 전달 = 이름 바인딩

함수를 호출하면, **인자로 넘긴 객체에 매개변수 이름이 바인딩**된다.
`b = a`와 완전히 같은 일이다.

```python
def f(x):        # 호출되면: x = <넘어온 객체>  (화살표 연결)
    ...

a = [1, 2, 3]
f(a)             # 내부에서 x가 a와 같은 객체를 가리킴
```

u4(00장)에서 본 그림 그대로다 — 호출 시 프레임이 생기고,
매개변수는 그 프레임의 지역 변수로서 넘어온 객체를 가리킨다.
그래서 u1에서 `hold(obj)` 안의 refcount가 하나 더 높았던 것이다.

## 개념 2 — 그래서 "값도 참조도 아니다"

전통적 용어로 설명하면 오히려 헷갈린다.

**"값에 의한 전달"(pass by value)이 아니다** — 객체를 복사하지 않는다.
큰 리스트를 넘겨도 복사본이 안 생긴다. 화살표만 넘어간다.

**"참조에 의한 전달"(pass by reference)도 아니다** — 함수 안에서
매개변수를 **재대입**해도 바깥 이름은 안 바뀐다.

```python
def rebind(x):
    x = [9, 9]       # 재대입 — 안쪽 화살표만 옮김
a = [1, 2, 3]
rebind(a)
print(a)             # [1, 2, 3] — 안 바뀜! (참조 전달이면 바뀌어야 함)
```

정확한 이름은 **"객체 참조에 의한 전달"(pass by object reference)**
또는 **call by sharing**이다. 화살표(참조)가 전달되지만,
그 화살표 자체를 바깥과 공유하는 건 아니다.

## 개념 3 — 결론은 u2의 재대입 vs 변경

함수 안에서 무엇을 하느냐로 갈린다.

**변경(mutation)** → 바깥에 반영됨 (같은 객체를 수정하니까)
```python
def mutate(x):
    x.append(4)      # 객체 자체를 수정
a = [1, 2, 3]
mutate(a)
print(a)             # [1, 2, 3, 4] — 바뀜
```

**재대입(rebinding)** → 바깥에 반영 안 됨 (안쪽 화살표만 옮기니까)
```python
def rebind(x):
    x = [9, 9]       # 화살표를 새 객체로
a = [1, 2, 3]
rebind(a)
print(a)             # [1, 2, 3] — 안 바뀜
```

u2의 규칙 그대로다: `x.append()`, `x[0]=`는 변경, `x =`는 재대입.
**함수 인자에서도 똑같이 적용된다.**

## 개념 4 — 불변 객체는 애초에 헷갈릴 일이 없다

정수·문자열·튜플은 **변경 자체가 불가능**하다.
그래서 함수 안에서 할 수 있는 건 재대입뿐이고, 바깥은 절대 안 바뀐다.

```python
def add_one(n):
    n += 1           # 정수는 불변 → 새 객체 생성 → 재대입
    return n
x = 5
add_one(x)
print(x)             # 5 — 안 바뀜
```

"불변 객체는 값처럼 동작하고, 가변 객체는 참조처럼 동작한다"고
느껴지는 이유가 이것이다. 실제로는 둘 다 같은 방식(화살표 전달)인데,
불변은 변경이 불가능해서 재대입만 남을 뿐이다.

## 개념 5 — 그 유명한 가변 기본 인자 함정, 최종 정리

00장에서 봤던 `def f(x=[])`를 이제 완전히 설명할 수 있다.

```python
def append_to(item, target=[]):
    target.append(item)
    return target

append_to(1)         # [1]
append_to(2)         # [1, 2]  — 왜?!
```

- 기본값 `[]`는 `def` 실행 시 **한 번** 만들어져 함수 객체의
  `__defaults__`에 붙는다 (u2/00장).
- 호출할 때 `target`이 **그 하나의 리스트**를 가리킨다 (이번 유닛).
- `append`는 **변경**이라 그 객체가 계속 자란다 (u2).

세 유닛의 지식이 이 한 함정에 다 모인다. 해결:

```python
def append_to(item, target=None):
    if target is None:       # is None — u3
        target = []          # 호출마다 새 리스트
    target.append(item)
    return target
```

## 자바와 비교 — "자바도 사실 같다"

흔한 오해: "자바는 값 전달, 파이썬은 참조 전달." **둘 다 틀렸다.**

자바도 파이썬과 **똑같이** 동작한다. 자바는 "값에 의한 전달"인데,
그 값이 **객체의 경우 참조(주소)값**이다. 즉 참조를 값으로 복사해 넘긴다.

```java
void mutate(List<Integer> x) { x.add(4); }   // 바깥 리스트 바뀜 (변경)
void rebind(List<Integer> x) { x = newList; } // 바깥 안 바뀜 (재대입)
```

파이썬과 결과가 완전히 같다. 자바를 정확히 이해했다면 파이썬 인자 전달은
새로 배울 게 없다 — 용어만 "pass by value of reference"에서
"pass by object reference"로 바뀔 뿐이다.

차이는 불변 타입이다. 자바 원시 타입(`int`)은 진짜 값 복사라 함수 안
`n++`가 정수 자체를 바꿀 수 있(는 것처럼 보이)지만, 파이썬 정수는
불변 객체라 재대입만 된다. 결과(바깥 안 바뀜)는 같다.

## 백엔드 관점

- **의도치 않은 수정 방지**: 함수에 dict/list를 넘길 때, 함수가 그걸
  변경하면 호출자의 데이터가 바뀐다. "이 함수가 인자를 건드리나?"를
  항상 의식해야 한다. 건드리지 않는 게 기본값이어야 한다.
- 방어적 복사: 원본을 지켜야 하면 함수 안에서 `x = list(x)`로 복사 후 작업.
- 가변 기본 인자는 절대 쓰지 않는다. 린터(ruff, pylint)가 잡아준다.

## 실무 규칙

- 함수가 인자를 변경(mutate)하면 그 사실을 이름이나 독스트링으로 알린다.
  `sort_in_place`처럼. 아니면 새 객체를 반환하고 원본은 안 건드린다.
- 기본 인자로 `[]`, `{}`, `set()` 등 가변 객체를 쓰지 않는다. `None` 센티넬 사용.

## 3문장 요약 (직접 작성)

1. 파이썬은 매개변수가 전달될때, 객체의 참조값이 전달되는 call by sharing 방식이다.
2. mutation 연산을 하게되면 전달된 객체가 바뀌고, rebinding을 하게되면 전달된 객체의 값의 변화는 없다.
3. 하지만 정수나 문자열 같은 불변 객체는 mutation 연산 자체가 없다.
