# u3. 언패킹 — 왼쪽도 구조다

## 지도 확인

u1(이터레이터), u2(슬라이싱)에 이어 시퀀스의 세 번째 축이다.
`a, b = 1, 2` 같은 언패킹은 매일 쓰지만, 그 밑에는 u1의 이터레이터
프로토콜이 깔려 있다. `*rest`, 중첩 분해, `a, b = b, a`의 원리까지 본다.

## 개념 1 — 대입의 왼쪽에 구조를 쓸 수 있다

```python
a, b = 1, 2           # a=1, b=2
a, b, c = [10, 20, 30]
(x, y), z = (1, 2), 3 # 중첩도 됨
```

오른쪽을 순회해서 왼쪽 구조에 하나씩 꽂는다. **개수가 안 맞으면 에러다.**

```python
a, b = [1, 2, 3]      # ValueError: too many values to unpack
a, b, c = [1, 2]      # ValueError: not enough values
```

## 개념 2 — 이터러블이면 뭐든 언패킹된다

u1과 연결된다. 언패킹은 **오른쪽을 순회**하므로, 이터러블이면 다 된다.

```python
a, b, c = "xyz"           # 문자열도 (a='x', b='y', c='z')
a, b = {1: "a", 2: "b"}   # dict는 키를 (a=1, b=2)
a, b, c = range(3)        # range도
a, b = (x for x in [1,2]) # 제너레이터도
```

내부적으로 `iter()`를 호출해 값을 하나씩 뽑아 왼쪽에 배정한다.

## 개념 3 — swap 관용구의 진실

```python
a, b = b, a           # 두 변수 교환. 임시변수 불필요
```

이게 되는 이유: 파이썬은 **오른쪽 전체를 먼저 평가**해서 튜플을 만들고,
그 다음 왼쪽에 푼다.

```python
a, b = b, a
# 1) 오른쪽 (b, a) 평가 → 튜플 (기존b, 기존a) 생성
# 2) 왼쪽에 언패킹 → a=기존b, b=기존a
```

순서대로 대입하는 게 아니라 **스냅샷을 먼저 찍는다.** 그래서 겹쳐도 안전하다.

```python
nums = [1, 2, 3]
i = 0
i, nums[i] = 1, 99    # i가 언제 바뀌나?
# 오른쪽 (1, 99) 먼저 평가 → i=1, 그 다음 nums[i]... i는 이제 1? 0?
```

이런 미묘한 경우는 바이트코드로 확인한다 (예제에서).

## 개념 4 — 별 표현식 *rest

```python
first, *rest = [1, 2, 3, 4]      # first=1, rest=[2,3,4]
*init, last = [1, 2, 3, 4]       # init=[1,2,3], last=4
a, *mid, z = [1, 2, 3, 4, 5]     # a=1, mid=[2,3,4], z=5
```

**`*`가 붙은 곳이 나머지를 리스트로 쓸어담는다.** 규칙:

- `*` 변수는 **최대 하나**만 가능 (`*a, *b = ...`는 에러 — 경계가 모호)
- `*` 변수는 **항상 list** (튜플을 풀어도 list가 됨)
- 나머지가 없으면 **빈 리스트**

```python
first, *rest = [1]               # first=1, rest=[]
```

**실무 관용구**: 머리와 꼬리 분리
```python
head, *tail = items
cmd, *args = user_input.split()
```

EP는 `data[0]` + `data[1:]` 슬라이싱보다 `first, *rest`를 권한다 —
인덱스 실수가 없고 의도가 드러난다.

## 개념 5 — 중첩 언패킹

구조가 깊어도 왼쪽이 오른쪽 모양을 그대로 그리면 된다.

```python
(a, b), (c, d) = (1, 2), (3, 4)
for (name, age), score in [(("kim", 20), 90), (("lee", 25), 85)]:
    print(name, age, score)
```

for문에서 특히 유용하다. `enumerate`, `dict.items()`, `zip`의 결과를
바로 분해한다 (u4에서 다룸).

```python
for i, (k, v) in enumerate(d.items()):
    ...
```

## 개념 6 — 함수 호출의 * 와 ** (맛보기)

같은 `*` 기호가 함수에서도 쓰인다. 방향이 반대다.

```python
def f(a, b, c): ...

args = [1, 2, 3]
f(*args)              # 언패킹해서 넘김 = f(1, 2, 3)

kwargs = {"a": 1, "b": 2, "c": 3}
f(**kwargs)           # dict를 키워드 인자로 = f(a=1, b=2, c=3)
```

- 대입 왼쪽의 `*` = **모으기** (여러 개 → 리스트)
- 함수 호출의 `*` = **펼치기** (리스트 → 여러 개)

정의부의 `*args`/`**kwargs`는 04장(함수 호출 메커니즘)에서 정식으로 다룬다.
지금은 "같은 기호가 모으기/펼치기 양방향"만 알면 된다.

## 자바와 비교 — "없는 기능이다"

자바에는 언패킹이 **없다.** 여러 값을 한 번에 받으려면 배열 인덱스나
객체 필드를 하나씩 꺼내야 한다.

```java
int a = arr[0], b = arr[1];       // 파이썬: a, b = arr
// swap
int tmp = a; a = b; b = tmp;      // 파이썬: a, b = b, a
```

자바 records(16+)와 패턴 매칭이 부분적으로 비슷하지만,
파이썬만큼 자유롭게 대입 왼쪽에서 분해하진 못한다.
이건 파이썬 고유의 편의라 자바 감각으로는 새로 배워야 하는 부분이다.

## 백엔드 관점

- 함수가 여러 값을 튜플로 반환하면 호출부에서 바로 분해한다.
  `name, email = get_user()`. dict보다 가볍고, 순서가 계약이 된다.
- `first, *rest = args` 패턴은 CLI 파싱, 라우팅에서 흔하다.
- `for k, v in d.items()`, `for i, x in enumerate(xs)`는 필수 관용구다 (u4).
- 과도한 언패킹(`a, b, c, d, e = ...`)은 오히려 가독성을 해친다.
  5개 넘으면 dataclass나 NamedTuple을 고려한다 (17장).

## 실무 규칙 (EP 연결)

- 인덱스로 여러 개 꺼내는 대신 언패킹을 쓴다 (EP Item 6).
- 머리/꼬리 분리는 슬라이싱보다 `first, *rest` (EP Item 16).
- swap은 임시변수 없이 `a, b = b, a`.
